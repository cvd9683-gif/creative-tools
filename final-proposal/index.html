SAY: Show Up is the practice coach I built for the midterm. You pick a challenge, get a brief, and run a timed sprint — but you design in Figma, Illustrator, or on paper. When time's up you paste your piece onto a wall inspired by NYC wheatpasted posters. AI critique is optional. In testing, the big surprise was that people tried to design inside the app. The timer was confusing, and the Wall, friend mode and AI feedback had bugs. I've fixed the intro, Wall navigation and friend mode. Still open: the sprint has too many steps, and two accounts can end up sharing the same work. SAY: Idea two: a small companion for when you have several AI chats going at once. Example: I'm making a gig poster — Claude is writing headlines, ChatGPT is suggesting palettes, Gemini is looking up venues. It looks like the carnival game with little horses racing on parallel tracks. One lane per chat. When the AI is working, its horse runs. When it reaches the finish line, the answer is ready and it's your turn — that lane lights up. A horse at the gate means nothing is running. Each lane shows how many messages you've sent, and the bar at the top adds them up against a limit you set yourself, so you notice before you burn through your plan. Open jumps to that chat. Handoff writes a summary you can carry to another tool. HONEST DETAILS ABOUT THE HORSE • What I can detect: whether a chat is working or finished — by watching the chat page (e.g. the stop button appears while it's writing). NEEDS TESTING; it breaks if the site changes its layout. • What I can't detect: how far along the AI really is. No chat site reports "60% done". So while it's working, the horse moves with time (or with how much text has streamed in) — it's an animation that says "still going", not a real percentage. The finish is real: it's when the answer is done. • "Your turn" = answer finished and you haven't opened that chat since. That's inferred, not reported by the service. • Message counts: counted by watching your sends on the page, only while the extension is running. NEEDS TESTING. • Usage limit: one the person sets (e.g. 30 messages). Real plan limits aren't readable — Claude shows them only as % bars in its own Settings > Usage, with no API. Never show a made-up "tokens left". • Design tension for feedback: making usage visible could make it feel like a game you want to play more. So no points, streaks, or rewards for sending; the horse rewards nothing, it just tells you when to look. • Sound idea: a soft bell when a horse finishes, so you can stop watching tabs. • All chats and numbers here are made up.

WHERE EACH NUMBER COMES FROM • Messages: counted by the extension on supported sites, only while it's running. Measured. • Tokens: an estimate from text length — always labeled "≈". Not the provider's count. Exact token counts only exist on developer APIs (Anthropic responses include input/output token usage and rate-limit headers: platform.claude.com/docs/en/api/rate-limits; even count_tokens is "an estimate"). • Plan usage left: not readable. Claude shows % bars + reset times in Settings > Usage (support.claude.com/en/articles/11647753, /9797557); no API exposes it. The report would link there. • "Was it useful?": entered by the person, one tap per chat. • Pattern: simple local check for repeated, near-identical requests in one chat. Neutral wording — repeating can be exploring. • Skills from GitHub (idea, NEEDS TESTING): use GitHub's official search API — not scraping — to look for public repos and SKILL.md files that match the task (e.g. "poster copy", "brand voice"). On Nov 8 a repository search for "claude skills" returned results without trouble; the API is rate-limited and code search needs a signed-in token. The AI reads the top few READMEs/SKILL.md files and explains in one line what each does; the person decides. Cautions: shared skills vary in quality and can include scripts — only suggest, never install automatically, and show the source repo. "Saves tokens" is a hypothesis: a skill can save re-explaining context, but I have no measurement, so the slide says "set your style once", not a number. The skill on the slide is made up. • Prompt tip + handoff: the person picks a conversation (from the page, or pasted / exported). Only that text goes to a model (Claude Messages API with structured outputs, so the handoff always has the same fields — platform.claude.com/docs/en/build-with-claude/structured-outputs). The tip has to point to the messages it's based on. Draft only; the person edits it. Needs a clear opt-in each time since it's chat content.
